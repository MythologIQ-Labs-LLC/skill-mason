# Prism eligibility candidate (overlay)

**Status: candidate, not adopted.** This directory is the project-owned part of a Prism application: the files Skill Mason authored, plus one patch. It is **not** a template instance, and its presence does not make Skill Mason Prism-built. Adoption is the owner's decision in [ADR-0003](../docs/adr/0003-prism-application-adoption.md).

It exists so that the first eligibility decision can be rebuilt and re-verified from pinned inputs without copying the upstream template into this repository.

## The decision

A request is exactly four bytes. Each is a code for one fact about one pinned source method.

| Byte | Fact | Admitted code | Refusal reason |
| --- | --- | --- | --- |
| 0 | Evidence state | `1` | `EVIDENCE_UNQUALIFIED` |
| 1 | Reuse rights | `1` | `RIGHTS_UNRESOLVED` |
| 2 | Authority needed against the caller's ceiling | `1` | `AUTHORITY_EXCEEDED` |
| 3 | Coverage of the requested essential outcome | `1` | `OUTCOME_UNCOVERED` |

- All four admitted: the response is `eligible`.
- Otherwise: `refused:` followed by a space and the reason for each failing fact, in byte order.
- Any other length: `invalid request`.

Only `1` is admitted. `0`, `2`, `255` and every other value refuse, so a code nobody has defined yet cannot make a method eligible. What `0` or `2` *mean* for each fact is not modeled, on purpose: the model needs no meaning for a value it refuses.

### What is proved, and what is not

Lean proves `eligible_decides`: for every request, `eligible request = true` exactly when all four codes equal `1`, using the `propext` axiom only. The conformance test additionally fixes that the response is decided by that same `eligible`, that exactly one code is admitted, and that a wrong length is invalid.

Not proved, and not claimed: that a code is true. The application decides over four bytes it is handed. Who sets each byte, from what evidence, is outside the model and is listed as an open owner decision in ADR-0003.

### Acceptance vectors

| Request (hex) | Response |
| --- | --- |
| `01010101` | `eligible` |
| `00010101` | `refused: EVIDENCE_UNQUALIFIED` |
| `01000101` | `refused: RIGHTS_UNRESOLVED` |
| `01020101` | `refused: RIGHTS_UNRESOLVED` |
| `01010001` | `refused: AUTHORITY_EXCEEDED` |
| `01010100` | `refused: OUTCOME_UNCOVERED` |
| `00000000` | `refused: EVIDENCE_UNQUALIFIED RIGHTS_UNRESOLVED AUTHORITY_EXCEEDED OUTCOME_UNCOVERED` |
| `ff010101` | `refused: EVIDENCE_UNQUALIFIED` |
| `010101` | `invalid request` |
| `0101010101` | `invalid request` |
| empty | `invalid request` |
| 512 zero bytes | `invalid request` |

`tests/test_prism_overlay.py` decodes these from the model and checks them against an independent Python oracle. That is a consistency check on the authored file, not a Prism verification.

## Rebuild and verify

**On hold for any machine that holds credentials** ([issue #9](https://github.com/MythologIQ-Labs-LLC/skill-mason/issues/9)). The SDK image comes from a personal registry namespace. Run it only on a disposable, credential-free, isolated runner with its own Docker daemon. The wrapper refuses to start otherwise.

Needs Docker, about 25 GB of disk for the SDK image, and network for a cold cache.

```bash
git clone https://github.com/UOR-Foundation/template template
git -C template checkout b64cc73c94773ed5bcc9d0549b1ae2c836fa1e0b
```

```bash
scripts/prism_instance.sh template work/prism
```

Commit `work` as a Git repository (the instance must be committed, and the commit that adds it sets the shrink-only ceiling), then run the complete gate. The wrapper stages its own copy and writes everything under `PRISM_GATE_WORKDIR`:

```bash
PRISM_GATE_WORKDIR=/var/tmp/gate-run-1 scripts/prism_reference_gate.sh work/prism host gate.log
```

The gate passes only if `gate.log` ends with `vv: the acceptance gate passed` and `GATE_EXIT=0`.

The wrapper in this repository has not yet been run against the SDK image, and by default it does not give the SDK container the Docker socket. If a stage turns out to need it, that is a finding to record, and `PRISM_GATE_DOCKER_SOCKET=disposable-daemon` is the explicit, throwaway-machine-only opt-in. Results of the runs made on 2026-11-17 with the earlier wrapper, including the planted defects and what was not established, are in the [evidence record](../docs/evidence/prism-phase0-20261117/README.md).

## Changing it

Follow the `prism-model-first` skill. Edit the model only inside a rebuilt instance, where `lexlean fmt`, `lexlean lock` and `prismpm verify` can judge the edit, then copy the canonical result back here and regenerate `template.patch`. Never hand-edit `lexlean.lock` or the `CONFORMANCE.md` hunk.
