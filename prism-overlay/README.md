# Qortara Skills Eligibility: project-owned Prism source (overlay)

**Status: candidate, not adopted.** This directory is the project-owned part of the Prism application **Qortara Skills Eligibility**: the files this project authored, plus one patch. It is **not** a template instance, and its presence does not make Qortara Skills Prism-built. The owner has accepted a nested `prism/` instance as the architecture direction in [ADR-0003](../docs/adr/0003-prism-application-adoption.md); installing it is a separate, qualified change that has not happened.

It exists so that the first eligibility decision can be rebuilt and re-verified from pinned inputs without copying the upstream template into this repository.

The application was first built under the name `Skill Mason eligibility`. A name is part of a holo's bytes, so the rename made a different artifact: the earlier digest `4092fea9…` and attestation `7bed00d0…` belong to the old name only and are not evidence for this one. The renamed application has no evidence of its own until its complete gate passes on the isolated runner; that run will be recorded under `docs/evidence/`.

## The decision

A request is exactly four bytes. Each is a code for one fact about one pinned source method.

| Byte | Fact | Admitted code | Refusal reason |
| --- | --- | --- | --- |
| 0 | Evidence state | `1` | `EVIDENCE_UNQUALIFIED` |
| 1 | Reuse rights | `1` | `RIGHTS_UNRESOLVED` |
| 2 | Authority needed against the caller's ceiling | `1` | `AUTHORITY_EXCEEDED` |
| 3 | Coverage of the requested essential outcome | `1` | `OUTCOME_UNCOVERED` |

- All four admitted: the response is `eligible`.
- Otherwise: `refused:` followed by a space and the reason for each failing fact, in byte order.
- Any other length: `invalid request`.

Only `1` is admitted. `0`, `2`, `255` and every other value refuse, so a code nobody has defined yet cannot make a method eligible. What `0` or `2` *mean* for each fact is not modeled, on purpose: the model needs no meaning for a value it refuses.

### What is proved, and what is not

Lean proves `eligible_decides`: for every request, `eligible request = true` exactly when all four codes equal `1`, using the `propext` axiom only. The conformance test additionally fixes that the response is decided by that same `eligible`, that exactly one code is admitted, and that a wrong length is invalid.

Not proved, and not claimed: that a code is true. The application decides over four bytes it is handed. Who sets each byte, from what evidence, is outside the model and is listed as an open owner decision in ADR-0003.

### Acceptance vectors

| Request (hex) | Response |
| --- | --- |
| `01010101` | `eligible` |
| `00010101` | `refused: EVIDENCE_UNQUALIFIED` |
| `01000101` | `refused: RIGHTS_UNRESOLVED` |
| `01020101` | `refused: RIGHTS_UNRESOLVED` |
| `01010001` | `refused: AUTHORITY_EXCEEDED` |
| `01010100` | `refused: OUTCOME_UNCOVERED` |
| `00000000` | `refused: EVIDENCE_UNQUALIFIED RIGHTS_UNRESOLVED AUTHORITY_EXCEEDED OUTCOME_UNCOVERED` |
| `ff010101` | `refused: EVIDENCE_UNQUALIFIED` |
| `010101` | `invalid request` |
| `0101010101` | `invalid request` |
| empty | `invalid request` |
| 512 zero bytes | `invalid request` |

`tests/test_prism_overlay.py` decodes these from the model and checks them against an independent Python oracle. That is a consistency check on the authored file, not a Prism verification.

## Rebuild and verify

**Never on a machine that holds credentials** ([issue #9](https://github.com/MythologIQ-Labs-LLC/skill-mason/issues/9)). The SDK image comes from a personal registry namespace. The wrapper refuses to start on a credentialed runner, and that refusal is the answer.

The supported way is the [isolated-runner workflow](../.github/workflows/prism-native-gate.yml), described in [Running the native Prism gate on an isolated runner](../docs/technical/prism-native-gate.md). It clones the template at the pin, builds the nested instance with `scripts/prism_instance.sh`, and runs the complete `just vv`, an offline repeat and the planted defects through `scripts/prism_native_gate.sh`. A pull request that changes this directory starts it.

By hand, on a disposable, credential-free machine with its own Docker daemon, about 25 GB of disk, and the internal network and proxy that workflow sets up:

```bash
git clone https://github.com/UOR-Foundation/template template
```

```bash
git -C template checkout b64cc73c94773ed5bcc9d0549b1ae2c836fa1e0b
```

```bash
scripts/prism_native_gate.sh nested . "$(git rev-parse HEAD)" template /var/tmp/prism-gate-run
```

The gate passed only if `/var/tmp/prism-gate-run/logs/sm01-vv.log` ends with `vv: the acceptance gate passed` and `GATE_EXIT=0`, and every row of `out/summary.tsv` says `PASS`.

## Changing it

Follow the `prism-model-first` skill. Edit the authored files, then let the workflow's `author` job run `lexlean lock` and `lexlean fmt` and commit the files exactly as it emitted them. The `nested` job refuses in seconds if the lock or the canonical form is stale. Never hand-edit `lexlean.lock` or the `CONFORMANCE.md` hunk.
